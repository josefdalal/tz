# סטוריבורד (שלב 5, תכנון)

נבנה בחמישה סעיפים, לפי הסדר, עם עצירה לבדיקה אחרי כל אחד:
- **א.** פורמט אפייה בינארי.
- **ב.** פיצול לשני עמודים.
- **ג.** storyboard.json.
- **ד.** מצב סטוריבורד בעורך.
- **ה.** הנגן.

המבנה מתוכנן כך ששכבת הטקסט ([text-layer.md](text-layer.md)) תיכנס בלי שינוי.

## א. אפייה בינארית

סצנה אפויה מפנה לקובץ: `scene.baked = { file: "S_002.tzb", count: 15200 }`. הקובץ יושב בתיקייה `baked/` בריפו ונכנס לבנייה דרך `import.meta.glob`, כמו קבצי הצורה. JSON של סצנה נשאר קטן, והנגן טוען גיאומטריה בלי worker ובלי דגימה.

הקובץ (`.tzb`) הוא gzip של מבנה עמודות, little endian:

| חלק | תוכן |
|---|---|
| magic | `TZB1`, ארבעה בתים |
| גרסה, דגלים | uint16, uint16 |
| count | uint32 |
| אורך כותרת | uint32 |
| כותרת | JSON ב UTF-8, מרופד לכפולה של 4: `meta` (bw, bh, s0, rMin, rMax, isImage) ו `fields` |
| עמודות | עמודה לכל שדה לפי הסדר ב fields, כל אחת מרופדת לכפולה של 4 |

כל שדה ב `fields` מתאר את עצמו: `{ name, type, min, max }`. `type` הוא u8 או u16, והערך המקורי הוא `min + q * (max - min) / maxQ`. השדות כרגע:

| שדה | סוג | דיוק |
|---|---|---|
| x, y | u16 | טווח הצורה חלקי 65535 (בסביבות 0.05 פיקסל) |
| r | u16 | |
| edge | u8 | |
| rand | u16 | |
| rgb | שלוש עמודות u8 | רק בצורה מתמונה |

בערך 13 בתים לעיגול לפני gzip, לעומת כ 110 ב JSON. שדה חדש לכל עיגול, למשל id, נעילה או צבע ידני לעריכה של עיגול בודד, מוסיפים כעמודה עם שם. קורא שלא מכיר את השדה מדלג עליו.

**קידוד:** src/scenes/bakedFormat.js, טהור ובלי DOM, כדי ש Node ישתמש בו בהמרה. gzip בדפדפן דרך CompressionStream ו DecompressionStream, וב Node דרך zlib.

**שמירה:** "אפייה" בעורך שולחת את הקובץ ל `/__baked` דרך ה plugin. בבנייה, בלי שרת, הקובץ יורד כהורדה.

**המרה:** סצנות עם האפייה הישנה (`baked.circles` בתוך ה JSON) ממשיכות להיקרא. `tools/convert-baked.mjs` ממיר אותן לקובץ ולהפניה.

## ב. שני עמודים

- `editor.html`: הכלי הנוכחי. הפאנל תמיד פעיל, בלי `?debug`.
- `index.html`: הנגן. בלי lil-gui ובלי worker, טוען את storyboard.json ואת הקבצים האפויים.

שניהם מייבאים את אותו מנוע מ `src/engine/`: מאגר, פיזיקה, תנועה, רינדור, מסגרת, layout, ומעבר טהור (evaluateAt). מה שתלוי בעורך נשאר ב `src/editor/`: פאנל, worker, אפייה, פריסטים ושמירה. שני העמודים הם `build.rollupOptions.input` ב vite.config.js.

## ג. storyboard.json

נשמר ב `storyboard/storyboard.json`, באותה תיקייה שבה ייכנס בהמשך `storyboard/text-style.json`. אותו מנגנון version ומיזוג כמו שאר הפריסטים.

```json
{
  "version": 1,
  "type": "storyboard",
  "playback": "scrub",
  "steps": [
    {
      "id": "s1",
      "scene": "intro",
      "hold": 800,
      "transition": "intro__triangle-ember",
      "text": null
    }
  ]
}
```

- `playback`: scrub (ברירת מחדל) או step.
- `hold`: אורך אזור העצירה בגלילה, בפיקסלי גלילה.
- `transition`: שם קובץ ב transitions/, או null. כשהוא null, הסגנון והגלילה הם ברירת המחדל. קובץ שה from וה to שלו לא תואמים לסצנות של הצעדים מקבל אזהרה בעורך.
- `text`: מקום שמור לשלב 6 (בלוק אחד: כותרת, גוף, קישור, מיקום לפי פריסות, נקודות כניסה ויציאה). כרגע תמיד null, והנגן מתעלם ממנו.

**ציר הגלילה:** לכל צעד יש אזור עצירה באורך hold. אחריו, אם יש צעד הבא, מגיע אזור מעבר באורך `scroll.distance` של המעבר. מהמיקום בגלילה הנגן גוזר את המצב:

```
{ step, phase: "hold" | "transition", local }
```

- בעצירה, `local` הוא בין 0 ל 1 לאורך ה hold. זה ה t המקומי ש text-layer.md צריך לכניסה וליציאה (inStart, inEnd, outStart, outEnd).
- במעבר, `local` הוא ה t של evaluateAt.

הפונקציה הזו טהורה, באותו עיקרון של המעבר: אותה גלילה נותנת תמיד אותו מצב.

**snap** הוא לנקודות העצירה. ב scrub, כל אזור עצירה הוא נקודת snap. ב step, מחווה אחת עוברת לצעד הבא.

## ד. מצב סטוריבורד בעורך

תיקייה "סטוריבורד" בעורך:
- **רשימת צעדים:** הוספה, מחיקה, והזזה למעלה ולמטה.
- **לכל צעד:** בחירת סצנה מהרשימה, hold, ובחירת מעבר לצעד הבא. הרשימה מסוננת לקבצים שה from וה to שלהם מתאימים, ויש אפשרות "ללא".
- **תצוגה מקדימה:** סרגל לאורך כל הסטוריבורד, שמשתמש באותה פונקציית מיפוי של הנגן.
- **שמירה:** ל storyboard/storyboard.json.

## ה. הנגן

- **הדף:** קנבס קבוע, Lenis לגלילה רכה, ו ScrollTrigger שממפה את הגלילה לפונקציה של ג.
- **מקור ה t:** במעבר, הוא מגיע מהגלילה ולא מניגון.
- **ערכי גלילה:** `smoothing` של המעבר מכוון את ה lerp של Lenis, ו `snapDelay` את ה snap.
- **מחוון התקדמות:** נקודה לכל צעד, ולחיצה על נקודה מנווטת אליו.
- **מצב step:** GSAP Observer, נעילה עד סוף המעבר, וסף לאיפוס האינרציה של משטח מגע.
- **מגע:** `touch-action` מאפשר גלילה. דחיפה של עיגולים במגע רק בגרירה ארוכה.

## נקודות חיבור לשלב 6

- **צעד:** `text` כבר קיים בכל צעד.
- **t מקומי:** הוא קיים בכל אזור עצירה.
- **מקום להגדרות הגלובליות:** `storyboard/`.
- **מערכת קואורדינטות:** הפריסות והמסגרת משותפות לצורות ולטקסט.
- **מכשולים:** הטקסט יוסיף מכשולים לפיזיקה בעזרת המנגנון של העכבר, שיוכלל לרשימת מכשולים. זה חלק משלב 6, לא מכאן.
